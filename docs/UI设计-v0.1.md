## 1. 三条立场（布局都是它的推论）

1. **界面不许比音频响。** 没有音效、没有闪烁、没有打断式弹窗。状态变化用颜色与 1 px 描边表达，
   不用位移与缩放——这个软件的全部价值是「不打扰」。
2. **「我在不在说话」必须是屏幕上最确定的信号。** 三重编码，缺一不可：
   顶栏 chip（「正在发送」）、自己的席位光环、底栏控件变绿。只变一个地方，
   用户在紧张对局里就会看漏，然后对着静音键喊话。
3. **数字只显示我们能负责的。** 软件预算逐项列出、设备段单列（`ADR-0010`）。
   绝不出现「端到端 22 ms」这种把麦克风的 139 ms 藏起来的说法。

## 2. 六屏与状态机

| 屏 | 目的 | 关键控件 | 对应状态机（技术设计 §5.4） |
|---|---|---|---|
| 1 连接 | 进得去，且知道连的是谁 | 地址、匿名/账号、**首次指纹（TOFU）**、最近服务器 | Disconnected → Authenticating |
| 2 频道内 · 网格 | 人少时看清谁在说 | 自适应席位网格、频道树、按人音量/静音/独听、麦克风电平 | InChannel |
| 3 频道内 · 说 | 说的时候只关心「在发」 | 语音激活状态灯、网络面板（展开） | InChannel（TX 中） |
| 4 设置 | 设备、档位、说话方式、自检 | 处理档四选一、热键、灵敏度、自检 | 任意态（模态） |
| 5 重连 | 弱网不撒谎 | 横幅「你的声音传不出去」、立即重试/断开 | InChannel → Reconnecting |
| 6 列表模式 | 人多时（12 人）扫得快 | 紧凑行：头像 / 电平 / 音量 / 静音 / 独听 | InChannel |

**为什么两种视图都要**：网格（≤6 人）靠脸和光环，一眼看出谁在说；列表（>6 人）靠行高密度，
12 人一屏放得下。切换器在频道头右侧，状态存在本地配置里，不随频道变。

**为什么不再画「/8」**：8 只是混音器的实现常数（`audio-core::mix` 的 `MAX_TRACKS`），
不是产品上限。UI 一旦画了分母，用户就会以为第 9 个人进不来。

### 2.1 频道树（子频道嵌套）

线格式已经支持嵌套：`ChannelState.parent_id`（0 = 根）与 `position`（同级排序）都在协议里，
`client-core::Roster` 也已经把 `parent` / `position` 镜像过来了。**所以这是纯 UI 工作**，
不需要改协议；缺的只是服务器侧的建树（现在只预建一个根频道「大厅」）。

规则：

- **层级最多 3 级**（分组 → 频道 → 子频道）。再深就没人看得清，而且 264 px 的左栏每级 14 px
  缩进，4 级之后频道名会被挤到 10 个字以内。
- **分组**是「不能加入的容器」：协议里用 `flags` 的 bit 3（值 8，现有位是 1/2/4）表示，
  没有这个位就是普通可加入频道——一个频道也可以既有子频道又能加入。
- **折叠**：分组与有子节点的频道都可折叠，状态记在本地配置里（按服务器 + 频道 id），
  不随会话丢失。折叠时在右侧显示**子树人数合计**（淡色，与「本频道人数」区分开）。
- **计数**：行右侧永远是「本频道人数」，不是子树合计；子树合计只在折叠时出现。
- **说话指示**：只在「本频道有人说话」时点亮；折叠的分组如果子树里有人说话，
  分组行亮一个小点（不然人躲进子频道就完全看不见了）。
- **排序**：同一父节点下按 `position`，相同则按名字。拖拽排序留到管理功能。

## 3. 规格

- **基准 1440×900**，最小 1120×720；左栏 264，网络面板 320（收起时不占宽度），底栏 92。
- **栅格** 8 px 基准；间距只用 4 / 8 / 12 / 14 / 16 / 20。
- **色板**（深色唯一）：

| token | 值 | 用途 |
|---|---|---|
| `--bg` / `--win` | `#0b0e11` / `#10141a` | 窗口外 / 窗口底 |
| `--surf` / `--surf2` / `--surf3` | `#151a20` / `#1b2129` / `#232b34` | 卡片 / 控件 / 悬停 |
| `--line` / `--line2` | `#242c36` / `#2e3844` | 1 px 分隔与描边 |
| `--tx` / `--tx2` / `--tx3` | `#e8ecf1` / `#98a3b0` / `#68727f` | 主 / 次 / 弱文字 |
| `--acc` | `#5fe3a1` | **只出现在「有声」相关处**：说话、发送、达标 |
| `--warn` / `--danger` | `#e8b45c` / `#f2686d` | 重连、设备风险 / 静音、错误 |

## 4. 关键交互

### 4.1 三种说话方式（默认：语音激活）

| 方式 | 何时发 | 优点 | 代价 |
|---|---|---|---|
| **语音激活**（默认） | VAD 判定「在说话」才发 | 省带宽、保护隐私（咳嗽、旁边说话不外传） | 门限要调；说话太轻会吃头一个字 |
| 按住说话 | 按住时发 | 最可控、最省 | 对局里手忙 |
| 常开 | 一直发 | 零延迟、零漏字 | 对方听得到键盘、风扇、呼吸 |

- **三者只差一件事：是否用 VAD 门控发送**。常开 = 门限永远打开。
- 判据是「**电平 ≥ 门限 且 VAD 概率 ≥ 0.5**」，滞回 **2 帧开 / 30 帧关**（吃掉词尾，
  也让一句话里的字间停顿不至于把流切碎）。链上没有 VAD 时自动退化成只看电平。
- 预缓冲是 **3 帧（30 ms）**，不是 300 ms：补发是一次**突发**，全部挤进对方抖动缓冲的
  一瞬间，而那里只有 25–40 ms 的余量（目标 20 / 上限 60 / 稳态 20–36）。补 30 帧会被对方
  裁掉，等于白补。要真做到 300 ms 得改协议加「这是一段突发」的标记，不做（`ADR-0015`）。
- 静默期**不完全静默**：每 200 ms 发一个占序号的保活标记（约 1.6 kbps）。不发的话，
  对方按序号空洞数丢包，5 秒静默就是 500 个「丢包」——丢包率是这个项目里最不该说谎的数字。
  接收端用 `ReceivePath::note_keepalive` 把它推过去但不记账。
- 任何模式下 `Space` 都是**强制发送**（按住即发，绕过 VAD），这条让用户不必为了「说一个字」
  去改设置。
- 优先级：**静音 > 闭听 > 强制发送 > VAD**。静音时按住 Space 也不发，控件显示「已静音」。
- 命令行的默认方式是 `open`（脚本与 e2e 断言「每帧一个包」），产品默认是 `vad`；
  两者共用同一条实现，只是入口的默认参数不同。

### 4.2 发送状态必须在 50 ms 内可见

VAD 触发到界面变绿 ≤ 50 ms，否则用户会重复说第一句。做不到就不要做淡入动画，瞬间切换。

### 4.3 按人控制：音量 / 静音 / 独听

- 独听语义是「只听他」，不是「把别人静音」。多人同时独听 = 这几个人都出声；
  **静音优先于独听**（自己点了静音，别人怎么独听都不会放出自己）。与 `audio-core::mix`
  的实测语义一致（C-29），UI 文案不能写成「屏蔽其他人」。
- 滑杆即时生效（增益一帧 10 ms 线性渐变，不会「咔」），不设「应用」按钮。
- 列表模式下控件常显；网格模式下悬停或聚焦时显示（键盘可达）。

### 4.4 网络面板口径（`ADR-0010`）

- 入口是频道头的 chip：**「网络 14 ms ▸」**（展开后变绿并显示「▾」）。收起时不占宽度，
  主区可以放更多席位。
- 面板上半是**软件预算**：采集 0.0 / 前处理 0.08 / 编码 0.14 / 网络单程 0.3 / 抖动缓冲 14.0 /
  播放 8.0 → 合计 **22.5 ms**，标「承诺口径」。
- 下半是**实时量**与**自检**。设备段（本机 175.3 ms，其中约 139 ms 是麦克风）用一句话单列，
  明确「不进上面的承诺值」。这不是免责声明，是让用户知道换麦克风才有用。

### 4.5 自检必须显式同意出声

「声学回环」按钮文案直接写「（会出声）」，点击后仍需一次确认；「数字回环」不出声，可随时点。
两个数字并列显示，让用户自己看出差额在哪一侧。

### 4.6 降噪档切换

切换是运行期操作（`stages::Crossfade`，20 ms 线性淡入），UI 显示 200 ms 的「切换中」。
档位卡片同时给出**延迟与 CPU 两个价格**：DFN3 的真实价格是 `30 ms 算法 + 20 ms 队列 = 50 ms`
（C-26），只写 30 会误导。

### 4.7 TOFU（首次信任）

首次连接显示完整 SHA-256 指纹与「信任并记住 / 不信任」，**默认不选中任何一个**。
指纹变化时直接拒绝连接，错误页给「查看新指纹 / 重新信任」，等价于 CLI 的 `--reset-trust`。

## 5. IPC 契约草案（前端 ↔ Rust）

原则来自技术设计 §5.1：**高频数据合并成 10–20 Hz 的一次事件**，前端不接触 PCM 与网络包。

```text
命令（前端 → Rust）
  connect { addr, identity: Anonymous | Account { user, password }, trust: TrustPolicy }
  disconnect
  join_channel { channel_id }
  set_voice { mode: Vad | Ptt | Open, threshold_db, preroll_frames, hotkey }
  set_ptt { down: bool }                        // 强制发送（Space）
  set_self { mute?: bool, deafen?: bool }
  set_user { user_id, volume?: f32, mute?: bool, solo?: bool }
  set_chain { tier: Passthrough | HighpassAgc | Rnn | Dfn3 }
  set_device { kind: Input | Output, id }
  set_view { Grid | List }
  selftest { kind: DigitalLoopback | AcousticLoopback }   // 声学需二次确认
  list_devices

事件（Rust → 前端）
  state    { phase, channel, error? }                       // 变更时
  members  { [ { user_id, name, mute, solo, volume } ] }    // 变更时（不每秒重建）
  meters   { talking, self_level, tx, frames_sent, chain_ms }  // 10–20 Hz，与 members 合并
  net      { jitter_ms, loss, rtt_p50, rtt_p95, underruns, ring_drops, kbps }  // 5 s
```

- `talking` 与 `level` 走 `meters`，不走 `members`。
- `chain_ms` 来自各环节 `latency_samples()` 之和，前端只显示、不算账。

## 7. 已定（2026-11-18 第三轮）
1. **分组用 `flags` bit 3（值 8）**：`ChannelState.flags & 8` = 分组容器，**不可加入**。
   proto 注释已更新，服务器 `on_join_channel` 会回 `PERMISSION_DENIED`（"这是分组，不能加入"），
   有测试钉住「被拒之后会话不留在任何频道里」。
2. **每频道默认 32 人**：`ServerConfig::default().max_channel_users = 32`，与
   `audio-core::mix::MAX_TRACKS` 对齐。频道满员时每个客户端最多混 31 路远端，仍落在 32 槽内。
   这个上限**不按子树累加**——分组下三个频道各 30 人互不影响。
   有测试钉住这个数字是跨 crate 约定（改一边必须改另一边）。

剩下真正没定的只有产品口味，不阻塞开工：分组是否需要重命名/排序的管理界面（P6 后期），
以及列表模式在 30+ 人时是否需要分组折叠（现在只折叠左栏）。
