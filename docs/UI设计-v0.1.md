## 1. 三条立场（先看这个，下面的布局都是它的推论）

1. **界面不许比音频响。** 没有音效、没有闪烁、没有打断式弹窗。状态变化用颜色与 1 px 描边表达，
   不用位移与缩放——这个软件的全部价值是「不打扰」。
2. **「我在不在说话」必须是屏幕上最确定的信号。** 三重编码，缺一不可：
   顶栏 chip（文字「正在发送」）、自己的席位光环、PTT 按钮的填充色。
   只变一个地方，用户在紧张对局里就会看漏，然后对着静音键喊话。
3. **数字只显示我们能负责的。** 软件预算逐项列出、设备段单列（`ADR-0010`）。
   绝不出现「端到端 22 ms」这种把麦克风的 139 ms 藏起来的说法。

## 2. 五屏与状态机

| 屏 | 目的 | 关键控件 | 对应状态机（技术设计 §5.4） |
|---|---|---|---|
| 1 连接 | 进得去，且知道连的是谁 | 地址、匿名/账号、**首次指纹（TOFU）**、最近服务器 | Disconnected → Authenticating |
| 2 频道内 · 听 | 看清谁在说、谁被静音 | 8 席位网格、频道树、按人音量/静音/独听、麦克风电平 | InChannel |
| 3 频道内 · 说 | 说的时候只关心「在发」 | PTT 大按钮、发送指示、网络面板 | InChannel（TX 中） |
| 4 设置 | 设备、档位、说话方式、自检 | 处理档四选一、热键、灵敏度、自检 | 任意态（模态） |
| 5 重连 | 弱网不撒谎 | 横幅说明「你的声音传不出去」、立即重试/断开 | InChannel → Reconnecting |

**为什么席位是固定 8 格而不是自动伸缩的网格**：8 人是硬上限（`mixer` 8 槽）。
3 个人时自动网格会留一大片空白（第一版稿件就是这个毛病），固定席位把「还剩几个位置」
变成一眼可见的信息，也让布局在任何人数下都不跳。

## 3. 规格

- **基准 1440×900**，最小 1120×720；左栏 264，网络面板 320（收起时 56 的竖轨），底栏 92。
- **栅格** 8 px 基准；间距只用 4 / 8 / 12 / 14 / 16 / 20。
- **色板**（深色为唯一主题，见 §7 问题 1）：

| token | 值 | 用途 |
|---|---|---|
| `--bg` | `#0b0e11` | 窗口外/最深底 |
| `--win` | `#10141a` | 窗口底 |
| `--surf` / `--surf2` / `--surf3` | `#151a20` / `#1b2129` / `#232b34` | 卡片 / 控件 / 悬停 |
| `--line` / `--line2` | `#242c36` / `#2e3844` | 1 px 分隔与描边 |
| `--tx` / `--tx2` / `--tx3` | `#e8ecf1` / `#98a3b0` / `#68727f` | 主/次/弱文字 |
| `--acc` | `#5fe3a1` | **只在「有声」相关的地方出现**：说话、发送、达标 |
| `--warn` / `--danger` | `#e8b45c` / `#f2686d` | 重连、设备风险 / 静音、错误 |

  绿色只给音频状态用，不给「确认」「保存」这类普通按钮——否则「在说话」就不再突出。
- **字体**：正文 13 px；数字一律等宽（`Cascadia Mono` + `tabular-nums`），
  因为延迟数字会跳动，比例字体跳宽会显得像故障。
- **对比度**：正文 `--tx2` 在 `--surf` 上约 5.6:1，达 WCAG AA；`--tx3` 只用于辅助信息。

## 4. 关键交互

### 4.1 优先级：静音 > 闭听 > PTT > 语音激活

- 静音（自己）永远赢：按住 PTT 也不会发送，此时 PTT 显示「已静音」而不是「正在发送」。
- 松手即停，停止延迟 ≤ 1 帧（10 ms）；不做「松手淡出」——那会让最后一个字被吃掉。
- **发送状态必须在按下后 ≤ 50 ms 可见**。做不到就不要做按键动画，宁可瞬间切换。

### 4.2 按人控制：音量 / 静音 / 独听

- 独听语义是「只听他」，不是「把别人静音」。差别在多人与优先级：
  多人同时独听 = 这几个人都出声；**静音优先于独听**（自己点了静音，别人怎么独听都不会放出自己）。
  这条与 `audio-core::mix` 的实测语义一致（C-29），UI 文案必须跟着这个语义走，不能写成「屏蔽其他人」。
- 滑杆即时生效（增益一帧 10 ms 线性渐变，不会「咔」），不设「应用」按钮。

### 4.3 说话指示

- VAD 来自链上**第一个给出有效值**的环节（高通 → 降噪 → AGC2，C-17 的定案）。
- UI 只呈现两态（在说 / 没说）+ 一条电平条，**不做跳动动画**：
  抖动会让人误判「是不是我在说」，而这是最不能误判的一件事。

### 4.4 网络面板口径（`ADR-0010`）

- 上半是**软件预算**：采集 0.0 / 前处理 0.08 / 编码 0.14 / 网络单程 0.3 / 抖动缓冲 14.0 / 播放 8.0
  → 合计 22.5 ms，标「承诺口径」。
- 下半是**实时量**与**自检**。设备段（本机 175.3 ms，其中约 139 ms 是麦克风）用一句话单列，
  并明确「不进上面的承诺值」。这句话不是免责声明，是让用户知道换麦克风才有用。

### 4.5 自检必须显式同意出声

- 「声学回环」会从扬声器放脉冲，按钮文案直接写「（会出声）」，点击后仍需一次确认。
- 「数字回环」不出声，可以随时点。两个数字并列显示，让用户自己看出差额在哪一侧。

### 4.6 降噪档切换

- 切换是运行期操作（`stages::Crossfade`，20 ms 线性淡入），UI 显示 200 ms 的「切换中」，
  不显示任何跳变；档位卡片同时给出**延迟与 CPU 两个价格**，因为 DFN3 的真实价格是
  `30 ms 算法 + 20 ms 队列 = 50 ms`（C-26），只写 30 会误导。

### 4.7 TOFU（首次信任）

- 首次连接显示完整 SHA-256 指纹与「信任并记住 / 不信任」两个按钮，**默认不选中任何一个**。
- 指纹变化时直接拒绝连接，错误页给「查看新指纹 / 重新信任」；等价于 CLI 的 `--reset-trust`。

## 5. IPC 契约草案（前端 ↔ Rust）

原则来自技术设计 §5.1：**高频数据合并成 10–20 Hz 的一次事件**，前端不接触 PCM 与网络包。

```text
命令（前端 → Rust）
  connect { addr, identity: Anonymous | Account { user, password }, trust: TrustPolicy }
  disconnect
  join_channel { channel_id }
  set_ptt { down: bool }
  set_self { mute?: bool, deafen?: bool }
  set_user { user_id, volume?: f32, mute?: bool, solo?: bool }
  set_chain { tier: Passthrough | HighpassAgc | Rnn | Dfn3 }
  set_device { kind: Input | Output, id }
  selftest { kind: DigitalLoopback | AcousticLoopback }   // 声学需二次确认
  list_devices

事件（Rust → 前端）
  state    { phase, channel, error? }                 // 变更时
  members  { [ { user_id, name, mute, solo, volume, talking, level } ] }
  meters   { self_level, tx, frames_sent, chain_ms }  // 10–20 Hz，与 members 合并在一次
  net      { jitter_ms, loss, rtt_p50, rtt_p95, underruns, ring_drops, kbps }  // 5 s
```

- `talking` 与 `level` 走 `meters`，不走 `members`——成员列表不该每秒重建。
- `chain_ms` 来自各环节 `latency_samples()` 之和，前端只负责显示，不算账。

## 6. 与当前实现的差距（评审时要一起看的诚实清单）

| UI 依赖 | 现状 | 缺什么 |
|---|---|---|
| 默认降噪档 | 客户端默认 `highpass,agc2`（`apps/client/src/config.rs`），**没有 RNNoise** | 稿子按「RNNoise 默认」画；要不要开是决策（§7 问题 4） |
| DFN3 档可选 | `Chain::from_desc` 会直接构造 `Dfn3`，打开 feature 后 185 次分配/帧跑进音频回调 | 先加「worker 档位拒绝装配」的防线，再做 Chain 级装配（P5 遗留） |
| 重连 | `audio_io::Watchdog` 只报 `Fatal` | 「收到 Fatal 后重建流」+ 真机拔插 10 次（P2-4） |
| 设备段自检 | `apps/loopback` 有双回环，客户端没有 | 把匹配滤波 + 时间戳法搬进客户端（`ADR-0010` 的硬要求） |
| 闭听（deafen） | 未实现 | 混音器已有主音量/静音接口，接线即可 |
| 麦克风测试 | 未实现 | 采集 5 s → 播放，走同一条 `SampleSource` 接缝 |
| 同账号双设备 | 频道成员按 `user_id` 记，第二台会把第一台挤出去 | 改按 session 记（已知限制，P6） |
| 8 人上限 | `mixer` 8 槽；服务器 fan-out 未强制上限 | 服务器侧要在 `JoinChannel` 时拒绝第 9 人，UI 才能把「3/8」当真 |

## 7. 待你决定（这 6 条定了我就往 `apps/app` 落）

1. **深色唯一主题**，还是也要浅色？（浅色会让「说话光环」的对比设计整套重做）
2. **席位网格**（固定 8 格，稿子这样）还是**紧凑列表**（人少时更省空间、人多时更整齐）？
3. **默认说话方式**：按住说话 / 语音激活 / 常开？（稿子：按住说话，热键 Space）
4. **默认降噪档**：RNNoise 默认（稿子这样），还是等 D6 盲听再定？
5. **网络面板默认收起**（稿子）还是展开？
6. **底栏放什么**：稿子是「静音 / 闭听」，设置走顶栏齿轮。要不要把设置也放底栏？
