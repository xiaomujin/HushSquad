# ADR-0014：桌面外壳（Tauri 2）独立成一个 workspace，不参与音频门禁

- **状态**：已定
- **日期**：2026-11-19
- **相关**：`docs/ADR/ADR-0013`（前端只是渲染器）；`docs/UI设计-v0.1.md` §5、§8；`docs/执行方案与步骤-v0.1.md` §8（P6）

## 背景

`ADR-0013` 定下了前端（`ui/`）只是渲染器，状态的真相在 Rust。剩下的问题很具体：
**这层壳放在哪个 workspace 里**。

根 `Cargo.toml` 的 `members = ["crates/*", "apps/*"]` 本来会把 `apps/app` 自动收进来，
依赖方向的注释（`ui → app → client-core`）也是照这个写的。但把 Tauri 放进根 workspace
会带来三件不想要的事：

| 代价 | 具体数字 / 事实 |
|---|---|
| 门禁变慢 | `tauri` 的依赖树有几百个 crate（实测首次编译 1 分 25 秒，dev profile），每次 `cargo clippy --workspace --all-targets` 都要过一遍 |
| CI 被系统库绑架 | Linux 上 Tauri 要 `libwebkit2gtk-4.1-dev`、`libsoup-3.0`、`libgtk-3`；现在的 CI 只装 `libasound2-dev`。少装一个，整个门禁红——**红的原因和音频代码毫无关系** |
| 许可证/来源检查被稀释 | `cargo deny` 读的是整个 workspace 的 `Cargo.lock`，GUI 那几百个 crate 会一起进许可证扫描。真出问题时，它挡住的不是音频链路 |

这条取舍不是洁癖：`audio-core` 已经有一条硬约束（不得依赖 tokio/axum/tower/hyper，
`scripts/check.ps1` 里有断言）。那条约束保护的正是「实时链路不被别的东西拖累」。
GUI 工具链属于同一类风险，只是换了个方向。

## 决策

1. **`apps/app` 是独立的 workspace**：`apps/app/Cargo.toml` 里有自己的 `[workspace]` 表，
   根 `Cargo.toml` 用 `exclude = ["apps/app"]` 把它排除（不 exclude 的话 `apps/*` 通配会把它
   扫进来，cargo 直接报 `multiple workspace roots found in the same workspace`）。
2. **代码只有一份**：`apps/app` 通过 path 依赖用 `hushsquad-client` / `audio-io` / `client-core`，
   与命令行客户端跑的是同一条链路。壳里**没有任何音频或网络逻辑**。
3. **外壳有自己的门禁**：`scripts/check-app.ps1`（`pnpm check` + `cargo fmt --check` +
   `cargo clippy -D warnings` + `cargo build`）。它不进 `scripts/check.ps1`，也不进 CI。
4. **接口方向不变**：`ui → app → client-core`。`apps/app` 只做三件事：开窗口、把 IPC 命令
   转成 `hushsquad_client` 的调用、把会话状态推回前端（一条 `Channel<Event>`，前端按 `kind` 分派）。
5. **会话观察点是普通 Rust trait**（`apps/client/src/host.rs` 的 `Host`），不带 tauri 依赖：
   视图类型只 derive `serde::Serialize`。这样换外壳（Web / 移动 / 无头）不用动 `apps/client`。

## 备选与被否原因

| 方案 | 被否原因 |
|---|---|
| 放进根 workspace，门禁加 `--exclude hushsquad-app` | `cargo deny` 没有等价的排除手段，GUI 的依赖照样进许可证扫描；而且「门禁命令要记得加 exclude」是一个迟早会忘的约定 |
| 放进根 workspace，CI 装齐 webkit 依赖 | 门禁时间与失败面都被 GUI 放大，而 Linux 上的 GUI 打包**本来就还没验证过**；现在加进去等于用一个没验证过的步骤去卡住已验证的步骤 |
| 把壳写成 `apps/client` 的一个子命令 | 窗口事件循环（tao）与客户端的 10 ms tick 抢同一个线程；`apps/client` 还要保持「能在没有图形环境的地方跑」（CI、服务器联调） |
| 用 Electron 而不是 Tauri | 与 `ADR-0013` 的取舍冲突（多一份 Node 运行时、体积、许可证面），且 WebView2 在目标平台（Windows）是系统自带 |

## 后果

- **好**：音频门禁与 GUI 工具链彻底解耦；`scripts/check.ps1` 一个字没改；
  命令行客户端与界面共用同一份会话实现，行为不会分叉。
- **代价**：
  - `apps/app` 有自己的 `target/`（两份编译产物，共享的 path crate 会编两遍）；
  - 根目录的 `cargo fmt --all` / `cargo test --workspace` **覆盖不到**它，
    必须记得跑 `scripts/check-app.ps1`；
  - **`apps/app` 不在 CI 里**。这是一条明确的欠账：等 Linux 打包真的跑通一次，
    再把「外壳门禁」加成独立 job（那时它才配卡住主干）。
- **观察到的坑**（写在这里省得下次再踩）：`apps/app` 的 `frontendDist` 是编译期内嵌的，
  所以改了 `ui/` 必须先 `pnpm build` 再 `cargo build`，否则窗口里跑的还是上一版资源。
  `tauri.conf.json` 的 `beforeBuildCommand` 只在 `tauri build` 时生效，`cargo build` 不触发。
