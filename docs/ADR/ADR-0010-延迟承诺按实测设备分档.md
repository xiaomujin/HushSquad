# ADR-0010：延迟承诺分档给出，且必须按实测设备拆分

- **状态**：已定
- **日期**：2026-11-17
- **相关**：技术设计 §2.2、附录 A；执行方案 P2-5 / P2-6；`docs/measurements.md` C-05 … C-14

## 背景

技术设计 §2.2 定了 L0/L1/L2 三档验收线，附录 A 把「嘴到耳」拆成 11 行预算。这套预算在纸面上自洽，
但 2026-11-17 的真机测量给出了一个预算表里没有的结论。本机 D1（声学往返，音效增强已关）= **175.29 ms**，拆开是：

| 段 | 实测 | 归属 |
|---|---:|---|
| 我们的播放路径（写入 → 设备输出） | 34.27 ms | 我们的代码 + 系统引擎 |
| 重采样（48 kHz ↔ 端点 192 kHz） | 2.07 ms | 系统引擎 |
| DAC 模拟 + 空气 + 麦克风输入 | **138.95 ms** | **用户的设备** |

那 139 ms 在**采集方向**，与我们的代码无关：采集端点没有 APO（`FxProperties` `fx=1`、无 CLSID）；
缓冲差分实验证明播放侧如实计入（缓冲 +21.3 ms → 延迟 +21.5 ms）；关掉音效增强只省 23 ms（APO 在播放侧）；
把端点格式从 192 kHz 改到 48 kHz 只省 2.07 ms。它是这只 USB 电容麦固件/驱动的内部缓冲。

问题在于：附录 A 把「采集缓冲（设备/驱动）」写成 5–10 ms 的常数。实测是 **139 ms**，高一个数量级。
预算表本身没错，但它描述的是**我们能控制的那部分**，不是用户听到的那个数。
若对外承诺一个端到端数字，这个数字要么是假的（软件够快，用户仍然听到 175 ms），要么只对某台机器成立。

## 决策

1. **禁止端到端单一数字承诺。** L0/L1/L2 的数值定义为**软件预算**——附录 A 第 2–10 行，即帧成组到解码混音、
   我们的代码能影响的部分——按档位承诺 p50/p95。设备段（第 1 行采集缓冲、第 11 行播放缓冲）**单列**，不进承诺值。
2. **对外表述按实测设备分档**：产品文案给区间并注明「取决于你的麦克风与声卡」；
   客户端的设备页给**本机实测值**与拆分明细，不给通用数字。
3. **客户端必须自带延迟自检**：首次启动、默认设备变更、用户手动触发时跑一次回环测量，
   呈现「本机嘴到耳 ≈ X ms，其中设备段 Y ms」。手段固定为**数字回环 vs 声学回环**：
   前者量我们的播放路径，后者量完整往返，**两者之差就是用户设备的采集代价**。
4. 任何新增环节仍须在附录 A 占一行；设备段那两行改为「实测填入，不预设」。

## 备选与被否原因

| 方案 | 为什么不用 |
|---|---|
| 对外承诺 35 ms（「我们的播放路径只有 34 ms」） | 用户听到的是 175 ms。数字漂亮但不可复现，且把我们不控制的段算成自己的功劳 |
| 用独占模式压延迟 | 独占只优化播放侧，救不了那 139 ms；且本机实测事件驱动独占根本不跑（C-10），只能在轮询下工作，不能作默认行为 |
| 让用户把端点默认格式改成 48 kHz | 实测只值 2.07 ms（C-14），却要改系统设置或写 HKLM |
| 把 139 ms 归因于 APO、要求关音效增强 | 已被推翻（C-08）：关掉只省 23 ms，且采集端点根本没有 APO |
| 文档里只写「设备相关」不给数字 | 等于放弃验收。没有数字就没有 D1，P2 无法结案 |
| 维护一份「已验证机型」清单 | 维护不起，用户换麦克风即失效；自检才是可扩展的做法 |

## 后果

**正面**：

- 承诺的数值是我们真正能负责的，可以分两级验收：离线链路进 CI，设备段真机测；
- 用户拿到的是自己机器的真值；「延迟高」能立刻定位到设备段还是软件段；
- 数字不可复现时责任边界清楚——这正是 P2 花两天拆延迟换来的东西。

**负面 / 接受的代价**：

- 客户端必须内置一套测量流程（脉冲串 + 能量加权匹配滤波 + 数字/声学两种回环），是本 ADR 带来的实际工作量；
- 声学回环要出声，必须在 UI 上说明并获得用户许可，不能静默播放；
- 拿不出「一行营销数字」，对外沟通成本更高；
- 附录 A 的合计区间从此只是**软件部分**的下界，不再是端到端预期。旧文档里「实测预期 p50 65 / 85」这类
  按端到端理解的数字作废。

**需要的验证**：

- 软件段已由 `loopback --loopback`（数字回环）覆盖：34.27 / 36.34 ms，相关度 1.000，见 C-11 / C-14；
- 自检流程本身需要一条实验：同机跑「数字 + 声学」两次，验证差额稳定落在设备段
  （本机已验一次：175.29 − 36.34 = 138.95 ms，n=3–5，极差 <0.9 ms）；
- macOS / Linux 的 D1 仍未测（P2-3 未完成），本 ADR 不预设它们的设备段数值。

## 证据

- 声学往返 175.29 ms（n=5，极差 0.899，相关度 0.68）；音效增强开启时 198.29 ms → APO 值 23 ms
  —— `docs/measurements.md` §1.1、C-12。
- 数字回环 34.27 ms（Realtek，192 kHz 渲染，n=3，极差 0.037）/ 36.34 ms（48 kHz 渲染，n=3，极差 0.046）
  —— §1.3、§1.3.1、C-11、C-14。
- 独占模式缓冲差分：512 帧 → 137.92 ms、1536 → 159.40 ms、3072 → 191.57 ms，1:1 跟随 —— §1.3。
- 采集端点无 APO：`Microphone (USB Condenser Microphone)`，`FxProperties` `fx=1`、无 CLSID —— §1.2。
- 工具与估计器：`apps/loopback`（`--impulse` 声学 / `--loopback` 数字 / `--render-rate` 单变量）、
  `crates/audio-io/src/impulse.rs`（能量加权匹配滤波，C-04）。
