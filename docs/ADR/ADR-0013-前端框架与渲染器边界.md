# ADR-0013：前端用 Svelte 5 + Vite + TS，且前端只是渲染器

- **状态**：已定
- **日期**：2026-11-18
- **相关**：技术设计 §2.3（非目标）、§4.2（设计原则）、§5.1（Tauri 工程形态）、§13 第 6 条（前端框架选型，本文结案）；`docs/UI设计-v0.1.md`

## 背景

技术设计 §5.1 把 UI 定成「单个 Tauri 2 工程、桌面与 Android 共用同一套 Web 前端」，
但 §13 第 6 条把**前端框架选型**留成了开放问题（原文：倾向轻量的 Svelte/Solid + 少量状态库）。
2026-11-18 的 UI 稿评审之后，这套界面的规模已经能量出来了：

| 维度 | 数量 | 来源 |
|---|---:|---|
| 屏 | 6（连接 / 网格 / 列表 / 说 / 设置 / 重连） | `docs/ui/mockup.html` |
| IPC 命令 | ~15 | `docs/UI设计-v0.1.md` §5 |
| 高频事件 | 10–20 Hz（电平、抖动缓冲） | 技术设计 §5.1 |
| 单屏成员上限 | 32（= `audio-core::mix::MAX_TRACKS`） | C-53、ADR 决策 2026-11-18 |
| 每成员控件 | 4（音量 / 静音 / 独听 / 状态） | 评审结论「常显」 |

这不是「一屏一函数」能撑住的体量：频道树是递归的、成员区有两种视图、设置页还会继续长
（设备选择、自检向导、服务器浏览、自动更新）。同时项目的工程纪律很严（`deny.toml`、实时路径零分配、
测试即门禁），所以「引入一整套 JS 生态」这个代价必须换来对得起它的收益。

## 决策

1. **前端栈：Svelte 5 + Vite + TypeScript**，状态用 Svelte 5 的 runes（`$state` / `$derived`），
   **不引额外状态库**（不要 Redux/Zustand/Pinia 那一层）。
2. **前端只是渲染器**（技术设计 §4.2 的强化版）：
   - 前端不碰 PCM、不碰网络包、**不算延迟账**；所有数字都是后端给的原样显示。
   - **状态的唯一真相在 Rust**。前端只持有「最近一次快照 + 增量」，不做本地真相，
     不做乐观更新（音量滑杆例外：拖动时本地跟随，松手以服务器回显为准）。
   - **IPC 契约集中在一个文件**（`ui/src/lib/ipc.ts`）：命令与事件的类型只在那里定义；
     将来可以用 `ts-rs` 从 Rust 结构体生成，消灭两边手工对齐。
3. **事件分两条通道**：
   - 低频「状态变了」（连接状态、频道树、成员增删）走 Tauri `emit`；
   - 高频「数字在动」（电平、VAD、抖动缓冲、RTT）走 Tauri 2 的 **`Channel<T>`** 流，
     20 Hz 合并推送，不在前端做定时器轮询。
4. **视觉 token 抽成 `tokens.css`**，`docs/ui/mockup.html` 与 `ui/` 共用同一份变量。
   稿子降级为**视觉参考**，实现以 `ui/` 为准；改稿必须同步 token 文件。
5. **开发期允许跑在浏览器里**：`ipc.ts` 提供一个 `MockBackend`（假数据、可脚本化状态），
   于是 `pnpm dev` 不开 Tauri 也能看界面；Tauri 侧实现同一个接口。

## 备选与被否原因

| 方案 | 为什么不用 |
|---|---|
| 纯手写 DOM + 100 行 store | 6 屏 + 递归树 + 双视图 + 32 行 × 4 控件，第 3 个页面之后就开始还债；省下的构建步骤换不回「状态与视图不一致」这类 bug 的排查时间 |
| React | 运行时更大；20 Hz 电平更新需要自己 `memo`/`useSyncExternalStore` 调优，等于给实时界面加一层要维护的性能优化 |
| Vue | 可接受，但没有比 Svelte 更强的理由；团队没有既有 Vue 资产 |
| Solid | 与 Svelte 同级（细粒度、小体积），但 Svelte 5 的 runes 更接近「普通 TS + 少量宏」，且文档/示例更多 |
| WASM 方案（Dioxus / Leptos / Yew） | 技术设计 §2.3 已把「纯 Dioxus 主 UI」列为**非目标**；WASM 同时抬高构建、调试与 WebView 兼容复杂度，收益只是「少写 JS」 |
| Electron | 体积与内存代价（~100 MB 起）与「轻量语音工具」的定位相反；Tauri 已在 §5.1 定案 |

## 后果

**正面**：

- 编译期产物、无虚拟 DOM，电平这类「每帧只变几个数字」的更新天然便宜；
- 组件化让频道树、成员卡片、设置页各自独立，新增页面约 100 行；
- 类型化 IPC + 单一契约文件，把「Rust 改了字段、前端没改」变成编译期错误；
- 构建步骤是 Tauri 的标准路径（`beforeDevCommand` / `beforeBuildCommand`），不发明新东西。

**负面 / 接受的代价**：

- 引入 node 工具链与 `node_modules`（约 200 个包），CI 多一步 `pnpm build`（实测约 30 s）；
  依赖面由 `pnpm audit` 与锁文件管理，不纳入 `cargo deny`。
- `docs/ui/mockup.html` 不再是唯一实现，存在「稿子与实现漂移」的风险 → 用共享 `tokens.css` 缓解，
  并规定「改视觉先改 token，再改组件」。
- Svelte 5 是较新的大版本（runes 语法），遇到生态问题要自己解决；接受，因为收益在编译期。

**需要的验证**：

- `pnpm build` 产物能被 Tauri 的 `frontendDist` 直接加载（无 dev server 也能起窗口）；
- 20 Hz 的 `Channel<T>` 推送在 WebView2 里不掉帧、不堆积（用真实 32 人列表压一次）；
- 前端在「后端事件断流」时显示「状态未知」而不是保持旧值（第 5 屏的语义）。

## 证据

- 规模与屏数：`docs/ui/mockup.html`（6 屏）、`docs/UI设计-v0.1.md` §2/§5；
- 人数上限与混音器对齐：`crates/audio-core/src/mix.rs` 的 `MAX_TRACKS = 32`、`docs/measurements.md` C-53；
- 工具链实测（本机）：node **v24.14.1**、pnpm **11.18.0**；
- 非目标依据：技术设计 §2.3 第 1 条（GPUI / 纯 Dioxus 主 UI）。
