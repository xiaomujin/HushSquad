# HushSquad 服务器部署

> 状态：单节点可用。**多节点不做** —— v1 的 fan-out 在单进程内完成，跨节点要先解决
> 「频道归属」这个协议问题（谁负责给某个频道的人转发），那是 P6 之后的事。

## 1. 它是什么

两个面，**故意分开**：

| 面 | 传输 | 端口 | 干什么 |
|---|---|---:|---|
| 控制面 | TLS 1.3 over TCP（ALPN `hushsquad/1`） | 64738/tcp | 握手、认证、频道与成员 |
| 语音面 | 加密 UDP（ChaCha20-Poly1305） | 64739/udp | 语音包 SFU 转发 |

控制面要可靠有序，语音面要低延迟可丢；混在一条连接上必然互相拖累。

服务器**只做四件事**：成员校验、`channel_epoch` 校验、fan-out、异常计数。
它不做混音 —— 按人调音量、静音某人、单独收听全是客户端本地的事，不占服务器带宽，
这也是 v1 选 SFU 而不是 MCU 的产品理由（技术设计 §8.1）。

## 2. 跑起来（不需要任何准备工作）

```bash
./hushsquad-server
```

就这样。第一次启动会自动做三件事，并把结果打印出来：

| 自动做的事 | 结果 |
|---|---|
| 建账号库 | `hushsquad.db`（SQLite） |
| 生成自签证书 | `hushsquad-cert.pem` / `hushsquad-key.pem`，SAN 含 `localhost`、`127.0.0.1`、`::1`、本机局域网 IP |
| 预建频道 | 一个「大厅」（想改就 `--channel 名字`，可重复） |

启动横幅长这样：

```text
HushSquad 服务器已启动
  控制面    0.0.0.0:64738
  语音面    0.0.0.0:64739（对外宣告 192.168.1.10:64739）
  账号库    hushsquad.db
  频道      大厅
  匿名登录  允许（上限 200 个）
  证书      hushsquad-cert.pem
  指纹      3A:7F:...:91
            （刚生成；客户端第一次连会自动记住它）
```

`--voice-host` 不写时会自动猜一个局域网 IP；猜不出来会明确警告并退回 `127.0.0.1`
（那样只有本机能连，警告里会写清楚）。

## 3. 加账号

```bash
./hushsquad-server adduser 张三     # 提示输入密码，不回显，问两遍
./hushsquad-server ls              # 看有哪些账号
./hushsquad-server passwd 张三     # 改密码
./hushsquad-server del 张三        # 删账号（它的设备绑定一起删）
```

密码以 argon2id 的 PHC 串存在 SQLite 里，**永远不落明文**。
账号库、证书都是**启动时读一次**；加人之后不需要重启（每次认证都查库）。

### 3.1 三种登录方式

| 方式 | 客户端怎么用 | 典型场景 |
|---|---|---|
| 匿名（设备号） | `hushsquad-client --server <地址>` | 临时拉人进来说两句 |
| 账号 + 密码 | `--server <地址> --user 张三` | 正式成员 |
| 免密（设备 token） | 同上，第一次输过密码之后就不用再输 | 日常 |

匿名登录可以关掉：`--no-anonymous`；上限用 `--max-anonymous <数量>`（默认 200）。
已经登记过的设备不受上限影响 —— 否则号建满之后本来在用的人也进不来了。

## 4. 换证书与端口

证书是自签的，客户端第一次连会记住指纹（TOFU）。换证书有两种情况：

```bash
# 主动换：删掉两个 pem 再重启，证书自动重新生成
rm hushsquad-cert.pem hushsquad-key.pem

# 用正规证书（Let's Encrypt 等）
./hushsquad-server --cert /etc/letsencrypt/live/voice.example.com/fullchain.pem \
                  --key  /etc/letsencrypt/live/voice.example.com/privkey.pem
```

**换完证书，客户端会拒绝连接**（这正是 TOFU 的意义）。确认是自己换的之后，在客户端上加
`--reset-trust` 连一次即可。

端口与对外地址：

```bash
./hushsquad-server --bind 0.0.0.0:64738 --voice-bind 0.0.0.0:64739 \
                  --voice-host voice.example.com --voice-port 64739
```

`--voice-host` / `--voice-port` 是**写进 ServerHello 让客户端去连的地址**，不是监听地址。
服务器躲在 NAT 后面时这两个值必须是公网可达的那个。

systemd 与 docker-compose 的模板在 `deploy/`。
## 5. 日志与指标

只输出两类行，都按行解析：

```text
metrics {"datagrams_in":1234,"bytes_in":98765,...,"dropped":{"bad_tag":0,"replay":3,...},"dropped_total":3}
event {"event":"voice_bound","session":7,"addr":"203.0.113.5:51234"}
```

**红线：日志里没有语音内容，也没有明文消息体。** 事件只有 id、地址、原因短名。
这条红线有一个测试在守：`server-core/src/events.rs` 里的事件字段名是白名单的，
谁想加一个 `payload` 字段都会红。

丢弃原因分桶（按**名字**索引，不按数组下标，所以重排枚举不会悄悄改坏仪表盘）：
`malformed` / `unbound` / `wrong_epoch` / `bad_tag` / `replay` /
`rate_limited` / `no_channel` / `no_targets` / `server_muted` /
`sender_mismatch`。

## 6. 容量

release 下测得的单包开销（`measurements.md` §5.1）：

| 项 | 耗时 |
|---|---:|
| 单包 AEAD 封装 / 解封 | 1.33 / 1.32 µs |
| fan-out 到 7 个听众 | 12.47 µs |

推论：一个 8 人频道、每人 100 pps，服务器占用约 **单核的 1.0 %**。
瓶颈不在密码学，也不在 fan-out —— 在带宽：`64 B/包 × 100 pps × 人数²`。
8 人时上行约 `8 × 7 × 104 B × 100 = 582 kB/s ≈ 4.7 Mbps`。

## 7. 防火墙

| 端口 | 协议 | 必需 |
|---|---|---|
| 64738 | TCP | 是（控制面） |
| 64739 | UDP | 是（语音面） |

UDP 被完全阻断时 v1 的降级是**报错并提示换端口/网络**，不做 TCP 隧道
（协议草案 Q2 待决；先量化发生率）。

## 8. 客户端

```bash
cargo build --release -p hushsquad-client

# 最省事：匿名进（不上账号）
./hushsquad-client --server 192.168.1.10

# 账号登录：会提示输密码，输过一次以后就不用再输
./hushsquad-client --server 192.168.1.10 --user 张三
```

就这样。端口默认 64738；证书第一次连自动记住；设备号自动生成并存在用户数据目录。

| 平台 | 本地状态文件 |
|---|---|
| Windows | `%APPDATA%\HushSquad\client.db` |
| Linux / macOS | `$XDG_DATA_HOME/hushsquad/client.db`（兜底 `~/.local/share/...`） |

想确认自己的设备号（匿名身份就是它）：

```bash
./hushsquad-client --show-device-id
# 设备号：A1B2-C3D4-E5F6-7890-1122-3344-5566-7788
```

常用变体：

```bash
# 只听不发（没麦克风）
./hushsquad-client --server 192.168.1.10 --user 张三 --no-mic

# 没声卡也能自检整条链路
./hushsquad-client --server 127.0.0.1 --no-speaker --tone 440 --run-for 10

# 换服务器证书之后，确认一次
./hushsquad-client --server 192.168.1.10 --reset-trust

# 有正规证书时固定它（不用 TOFU）
./hushsquad-client --server voice.example.com --ca fullchain.pem
```

跑完会打印一份汇总，含**语音面 RTT 的 p50/p95/p99**、丢包、抖动缓冲深度、实际收发节奏。

### 8.0 三种证书信任方式

| 方式 | 参数 | 说明 |
|---|---|---|
| TOFU（默认） | 无 | 第一次连记住指纹，之后变了就拒绝并提示 `--reset-trust` |
| 固定证书 | `--ca <pem>` | 只认这一张 |
| 不校验 | `--insecure` | 只用于本机调试，中间人可冒充 |
### 8.1 三个容易踩的点

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 报「扬声器打开的是 44100 Hz」 | 链路固定 48 kHz，v1 不做重采样 | `--list-devices` 挑一个支持 48 kHz 的，用 `--mic`/`--speaker` 指过去 |
| 报「等 BindAck 超时」 | 语音面 UDP 没通（防火墙 / NAT） | 确认 64739/udp 可达；`--voice-host` 必须是客户端真能连到的地址 |
| 汇总里节奏只有 64 Hz | Windows 定时器粒度 15.6 ms 没提升 | 正常路径会自动调 `timeBeginPeriod(1)`；若报「没能提升」，声音会断续，查权限/杀软 |
| 声音「空旷 / 发飘 / 有点失真」 | 2026-11-17 之前的版本里，漂移补偿的每次拼接都会抬 +3 dB（等功率交叉淡化的中点），每秒几十次（C-51） | 换这一版之后的二进制；仍有加工感就加 `--no-drift` 对比一次，能立刻判定是不是补偿器 |
| 汇总里「迟到 N 次，最长 X ms」不为 0 | 主循环被卡住（控制台被选中/暂停、磁盘或杀软抖动），采集环 160 ms 的余量被吃穿，于是「环满丢」开始计数 | 别在控制台里选中文本（QuickEdit 会阻塞写）、把输出重定向到文件、或加 `--stats-interval 0` |

### 8.2 抖动缓冲的旋钮

`--jitter-min` / `--jitter-max` 决定抖动缓冲的目标延迟区间（默认 20 / 60 ms）。
NetEQ 的目标延迟是**自适应**的，这两个值是它允许的范围：

| 环境 | 实测稳态 |
|---|---:|
| 干净环回（三个独立进程） | **14 ms**（上限 60） |
| 同进程满载（服务器 + 两个客户端 + 3 条测试并行） | 56 ms（上限 60）/ 81 ms（上限 80） |

也就是说上限只是**天花板**：负载与突发把它推高时缓冲会贴上去，干净环境下会落回下限附近。
想压低延迟就调小 `--jitter-max`；4G 上反而要留大一点。

统计行里的 `pacing=±Nppm` 是**对端发包节奏相对我们 tick 节奏**的偏差（`Δ序号 / Δtick − 1`）。
它量的是节奏，不是晶振：本机环回（两个进程共用一块时钟）实测稳定在 **−1000 ppm**，
说明我们自己的收发节奏就有约 0.1 % 的系统偏差（C-52，还没查清）。

**它要到 5 分钟后才显示**（之前是 `pacing=--`）。分辨率就是 `1/Δticks`：30 秒时 330 ppm、
5 分钟 33 ppm、1 小时 3 ppm。早期读数是量化噪声，不是漂移——故意不显示，免得误导。
`--no-drift` 把漂移补偿整个关掉（纯直通），只在对比「加工感是不是补偿器造成的」时用——
关掉之后两端晶振差要由抖动缓冲自己扛，长会话延迟会慢慢漂。

### 8.3 已知缺口

- **设备必须 48 kHz**：重采样（`rubato` 已在依赖里）还没接；
- **音频流 Fatal 不自动重建**：设备被拔会报一条错误，之后这一路就没声音了（P2-4 的活）；
- **不做回声消除**：外放 + 麦克风会啸叫，请戴耳机；
- **漂移补偿在抖动链路上做无效功**（C-37）：本机环回（RTT 0.1 ms、0 丢包）实测每秒仍有 ~74 个样本
  的无效拼接，量级与真机联网一致——说明推动它的主要是**我们自己两个进程的 10 ms 相位差**。
  拼接本身已经做到听不出来（等增益，C-51），但这份工是白做的，而且它正在替延迟预算兜底，
  所以不能简单关掉；要修得先修「NetEQ 为什么停不在目标延迟上」；
- **没有频道密码的界面**：协议位在（`flags` bit2、`JoinChannel.password`），v1 不做编辑入口；
- **没有图形界面**：这是命令行客户端；桌面外壳在 `apps/app`（Tauri 2 + `ui/`），
  复用同一套 `client-core` + `audio-core`。

## 9. 还没做的

诚实列出来，别当成已经有了：

- **证书热加载**：换证书要重启；
- **用户表热加载**：加人要重启；
- **多节点**：不做，见文首；
- **在线换钥**：`RekeyRequest` 现在只回当前 epoch（v1 允许靠重连换钥）；
- **真实网络下的容量验证**：上面的 1.0 % 是本机环回测的 CPU，不是带真实丢包的数字。
