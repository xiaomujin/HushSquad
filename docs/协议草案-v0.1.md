# HushSquad 协议草案 v0.1

> 状态：**草案，未实现，仅供评审**。日期 2026-11-16。
> 关联决策：ADR-0002（自建 UDP）、ADR-0003（只做 SFU）、ADR-0004（ChaCha20-Poly1305 / per-hop AEAD）、ADR-0009（冗余+FEC，不重传）、ADR-0011（MCU 仅占位）、ADR-0012（不与 Mumble 客户端互通）。
> 配套：`proto/hushsquad-control-v1.proto`。

## 0. 范围与设计取舍

| 项 | 决定 | 理由 |
|---|---|---|
| 面数 | **两个面**：控制面（TLS 长连接）+ 语音面（UDP） | 控制面要可靠有序，语音面要低延迟可丢；混在一条连接上必然互相拖累 |
| 控制面传输 | TLS 1.3 over TCP，ALPN `hushsquad/1` | 简单、可调试；QUIC 作为待决备选（Q4） |
| 语音面 | 自建 UDP，ChaCha20-Poly1305，per-hop AEAD | 见报告与 ADR-0004 |
| 互通性 | 不追求 Mumble 客户端互通 | 继承数据模型，不继承密码学与线格式 |
| 消息编码 | 控制面 protobuf（proto3）；语音面**手写二进制** | 语音包头不能有 protobuf 的 tag/varint 开销 |
| 服务发现 | 客户端手动填地址 + 收藏；服务器浏览器后置 | v1 不做服务器列表协议 |

**非目标**：ICE/STUN/TURN/SDP、群组密钥 E2EE、视频、MCU 混音、Mumble 兼容、文本聊天（消息类型预留）。

## 1. 标识与编号

| 名称 | 类型 | 分配者 | 生命周期 | 用途 |
|---|---|---|---|---|
| `session_id` | u64 | 服务器 | 一次控制面连接 | 会话主键；UDP 重绑定靠它，不靠五元组 |
| `user_id` | u32 | 服务器 | 账号级，跨会话稳定 | 身份、权限、音量记忆 |
| `sender_id` | u32 | 服务器 | 一次 session（**单调递增，永不复用**） | 语音包标识；同时参与 nonce 构造 |
| `channel_id` | u32 | 服务器 | 服务器级稳定 | 频道树 |
| `channel_epoch` | u16 | 服务器 | **全局单调**，任何频道成员快照变化时 +1（见 §12.2） | 拒绝跨频道/过期语音包 |
| `key_epoch` | u16 | 服务器 | 密钥轮换时 +1 | 语音密钥版本 |
| `voice_token` | 16 B | 服务器 | 一次 session | UDP 首包绑定凭证、反放大 |

为什么 `sender_id` 必须永不复用：nonce = sender_id ‖ seq，复用会导致 **(key, nonce) 重复**，ChaCha20-Poly1305 下这是灾难性错误。u32 单调分配在单进程生命周期内不可能用尽。

## 2. 连接建立时序

```text
Client                                          Server
  |  TCP connect + TLS1.3 (ALPN hushsquad/1)        |
  |------------------------------------------------>|
  |  ClientHello{protocol=1, client_ver, caps}      |
  |------------------------------------------------>|
  |<------------------------------------------------|
  |  ServerHello{session_id, sender_id, voice_host, |
  |    voice_port, voice_token, key_epoch, epoch,   |
  |    server_time_ms, limits}                      |
  |  Auth{password | device_token}                  |
  |------------------------------------------------>|
  |<------------------------------------------------|
  |  AuthResult{ok, user_id, permissions}           |
  |  ChannelSync{channels[], users[]}  (快照)        |
  |<------------------------------------------------|
  |                                                |
  |  === UDP Bind（语音面） ===                     |
  |  BindPacket{voice_token}   -------------------->|
  |  <-------------------  BindAck{server_time_ms}   |
  |                                                |
  |  VoicePacket{...}  <--------------------------> |
```

要点：

- **控制面先建、语音面后绑**：控制面完成认证后才拿到 `voice_token` 与语音端点，UDP 首包必须带 token；服务器对未认证源地址**不回应任何数据**（反放大）。
- **BindAck 顺带给出服务器时间**，客户端据此算 RTT 与时钟偏移估计（只做差值，不做绝对同步）。
- 语音面绑定失败（被防火墙拦、NAT 封 UDP）时，v1 的降级是**报错并提示换端口/网络**，暂不做 TCP 隧道。是否加 TCP 语音隧道是 Q2 待决项。

## 3. 密钥派生

```text
base = TLS1.3_Exporter(                                  // RFC 8446 §7.5
         label = "EXPORTER-hushsquad-voice-v1",
         context = session_id(8) || user_id(4) || voice_token(16),
         length = 64)

c2s_key(epoch) = HKDF-SHA256(base[0..32], salt = session_id, info = "c2s" || key_epoch)
s2c_key(epoch) = HKDF-SHA256(base[32..64], salt = session_id, info = "s2c" || key_epoch)
```

- 每个方向一个 32 B 密钥；`key_epoch` 变化即换钥（重连、或被服务器周期性轮换）；
- **nonce（12 B）= 0x00000000 ‖ sender_id(u32, BE) ‖ seq(u32, BE)**；
- AAD = 语音包头部 20 字节（见 §4），保证头部不可篡改；
- 重放防护：每个 sender 一个 64 包滑动窗口，窗口外或重复 seq 丢弃；
- 密钥轮换触发：每 2^28 包、每 1 小时、或客户端重连。轮换走控制面 `RekeyRequest/RekeyResponse`（或直接重连，v1 允许简化）。

> 安全说明：per-hop AEAD 意味着服务器可解密语音（可做成员校验与将来的 MCU）。若未来要 E2EE，需改成群组密钥 + 服务器转发密文，届时 `key_epoch` 语义要换成「群组密钥版本」。

## 4. 语音包格式（线格式，字节精确）

固定头 **20 字节**（大端），后接载荷，末尾 16 字节 AEAD tag：

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 1 | `magic` | 固定 `0x48`（H）；用于极早期丢弃垃圾包 |
| 1 | 1 | `version` | 当前 `0x01` |
| 2 | 1 | `flags` | bit0 有冗余帧；bit1 冗余为 PLC 占位；bit2 打点包；bit3 绑定包；bit4 静音帧（DTX 边界）；bit5-7 保留 |
| 3 | 1 | `red_len` | 冗余帧字节数，无冗余为 0 |
| 4 | 2 | `channel_epoch` | u16 BE；服务器 fan-out 前校验 |
| 6 | 4 | `sender_id` | u32 BE；s2c 方向用于区分说话人 |
| 10 | 4 | `seq` | u32 BE；每个 sender 每个 key_epoch 从 0 单调递增 |
| 14 | 4 | `timestamp` | u32 BE；48 kHz 采样计数，用于抖动缓冲与时序（回绕按 2^32 处理） |
| 18 | 2 | `opus_len` | u16 BE；0 表示无音频载荷（打点/绑定包） |
| 20 | `opus_len` | `opus_data` | Opus 帧（10 ms 或 20 ms） |
| 20+opus_len | `red_len` | `red_data` | 上一帧副本 |
| 末尾 16 | 16 | `tag` | ChaCha20-Poly1305 认证标签 |

**总开销**：20（头）+ 16（tag）+ 28（IP+UDP）= **64 字节/包**。设计文档附录 B 按 62 字节估算，差异约 2–3%，不影响结论（10 ms/32 kbps 时线上约 84 kbps）。

特殊包：

| 包型 | flags | 载荷 | 语义 |
|---|---|---|---|
| Bind（c2s） | bit3 | `voice_token` 16 B | 首次绑定源地址；**唯一不带 AEAD 的包**（服务器在该包前不认密钥） |
| BindAck（s2c） | bit3 | `server_time_ms` u64 + `sender_id` u32 | 绑定成功，给 RTT/偏移基准；**带 tag**，载荷 12 B，所以整包 48 B（与 Bind 的 36 B 不同） |
| Probe（c2s） | bit2 | `client_ts_us` u64 | 打点包，服务器原样回送 |
| ProbeAck（s2c） | bit2 | 同载荷回送 | RTT 测量，不参与抖动缓冲 |
| Silence（DTX 边界） | bit4 | 空 | 告知对端「我停止说话了」，用于 VAD 指示与 PLC 收尾 |

**校验顺序（服务器热路径，先便宜后昂贵）**：magic → version → 源地址是否已绑定 → channel_epoch 是否等于该频道当前 epoch → AEAD 验证 → **滑动窗口去重** → sender_id 是否等于该会话的 → 成员校验 → fan-out。

> **实装修订（2026-11-17，见 §12.3）**：原稿把「滑动窗口去重」放在 AEAD 之前。这是错的 ——
> `seq` 在明文头里，先更新窗口等于给一个能伪造源地址的攻击者「把窗口推走」的把手。
> 现在 AEAD 在前、窗口在后，并补了一条 sender_id 校验（原稿漏了，构成冒充漏洞）。

## 5. 控制面消息（字段号见 .proto）

| 方向 | 消息 | 说明 |
|---|---|---|
| C→S | `ClientHello` | 协议版本、客户端版本、设备信息、能力位 |
| S→C | `ServerHello` | session_id、sender_id、语音端点、voice_token、key_epoch、channel_epoch、服务器时间、限额 |
| C→S | `Auth` | oneof：`PasswordAuth{username, password}` / `DeviceTokenAuth{device_token}` |
| S→C | `AuthResult` | ok / 错误码 / user_id / 权限位 |
| S→C | `ChannelSync` | 频道树快照 + 用户快照（仅登录后与重连时发全量） |
| S→C | `ChannelAdded` / `ChannelRemoved` / `ChannelUpdated` | 增量 |
| C→S | `JoinChannel{channel_id}` / `LeaveChannel` | 加入/离开 |
| S→C | `UserJoined` / `UserLeft` / `UserUpdated` | 成员增量广播 |
| C→S | `SetSelfState{self_mute, self_deaf, ptt_active}` | 自身状态（PTT 状态也可只在语音包里表达，见 Q5） |
| C→S | `SetListening{channel_ids[]}` | 监听多个频道（Mumble 式 channel listening 的简化） |
| C→S | `Whisper{target_user_ids[], channel_id}` | 定向语音（只影响服务器 fan-out 目标集合） |
| C→S | `RekeyRequest{key_epoch}` / S→C `RekeyResponse{key_epoch}` | 密钥轮换 |
| 双向 | `Ping{ts_us}` / `Pong{ts_us}` | 控制面心跳，15 s 间隔，45 s 超时 |
| S→C | `Error{code, message, fatal}` | 错误；fatal 表示连接将关闭 |
| S→C | `Stats`（可选，1 Hz 汇总） | 服务器视角的丢包/延迟/负载，用于网络面板 |

**不占协议的东西（重要）**：按人调音量、静音某人、单独收听——全部是**客户端本地混音前的增益与过滤**，服务器不参与、不占带宽。只有 `Whisper` 改变 fan-out 目标集时才需要服务器。

## 6. 服务器语音面行为（SFU）

```text
on VoicePacket from session S:
  1. 绑定检查：源地址 → session；未绑定则只允许 Bind 包
  2. epoch 检查：pkt.channel_epoch == current_epoch(S.channel) 否则丢弃 + 计数
  3. 重放检查：per-sender 滑动窗口
  4. AEAD 验证（c2s_key）失败 → 丢弃 + 计数（连续失败 N 次断开会话）
  5. 目标集合 R = members(S.channel) - {S}，再按 Whisper/Listening 修正
  6. 对每个 r in R：用 s2c_key(r) 重新加密同一帧，seq 沿用发送者 seq，sender_id 原样保留 → sendto(r.addr)
```

注意第 6 步的语义：服务器**不重排、不重编号、不缓冲**，只换密文。这样接收端可以直接把「同 sender_id 同 seq」当成一条流做抖动缓冲。

失败策略：单个目标 sendto 失败（如 NAT 超时）不重试、不影响其他目标；连续失败 3 s 标记该目标需要重新 Bind。

## 9. 版本协商与兼容规则

- 语音包版本在 byte1；服务器遇到未知版本丢弃并计数，不做兼容尝试；
- 控制面 `ClientHello.protocol` 为主版本；服务器不支持则回 `UNSUPPORTED_VERSION` 并带上支持范围；
- protobuf 一侧遵循 proto3 规则：**未知字段必须忽略**，不得因未知字段报错；
- 新增能力走 `ClientHello.caps` 位图与 `ServerHello.caps`，双方都置位才启用；
- 破坏性改动必须提升主版本，不做「同一版本号下行为漂移」。

## 12. 实装修订（P5，2026-11-17）

写代码之前看不出、写下去才撞到的东西。每一条都改了实现，其中 1–4 条**改的是协议本身**，
因此记在这里而不是只写在代码注释里。

### 12.1 方向是线格式的一部分

§4 给 Bind 和 BindAck **同一个 flags 位（bit3）**，区别只在载荷长度（16 B token vs 12 B
时间戳+id）与「有没有 tag」。单看字节流无法区分：20+16 = 36 B 与 20+12+16 = 48 B 都可能
出现在网线上，而 36 B 从服务器方向看恰好也能凑成「16 B 载荷 + tag」。

**修订**：解析必须带方向。规则只有一条 —— **只有「客户端 → 服务器」的 Bind 是明文无 tag**，
其余一切（含 BindAck、Probe、ProbeAck、Silence）都走 AEAD。方向由谁在收包决定，
不需要额外的标志位。

### 12.2 \`channel_epoch\` 必须是全局单调计数器

§1 原稿写「频道成员快照变化时 +1」，字面实现就是每频道各自计数。那样两个频道会各自从
0 数到 1、2、3……，大面积撞号，于是「跨频道包被拒」这条安全性质**根本拦不住东西**。

**修订**：服务器维护一个全局单调的 epoch 发号器，任何频道的成员变化都让它 +1。
u16 会回绕，但 65536 次成员变化远长于任何一个在途包的生命（而且 key_epoch 换钥会重来）。

### 12.3 校验顺序：AEAD 必须早于窗口去重

§4 原稿：magic → version → 绑定 → epoch → **窗口去重 → AEAD** → 成员 → fan-out。
理由写的是「先便宜后昂贵」，但代价被低估了：\`seq\` 在**明文头**里，先按它更新窗口，
一个能伪造源地址的离线攻击者只要发一个 \`seq\` 很大的垃圾包，就能把窗口推到前面，
随后到达的合法包全被判「太老」而丢弃 —— 一条不需要带宽的拒绝服务。

**修订**：AEAD 在窗口之前。代价是每个包多一次 Poly1305 校验（100 B 载荷 1.33 µs，
8 人满负荷合计 0.8 ms/s），换掉一个可利用的漏洞。

### 12.4 补一条 sender_id 校验（原稿漏了，构成冒充）

原稿的 6 步里没有任何一步校验「头里的 \`sender_id\` 是不是这条会话的」。服务器按**源地址**
找会话，然后原样转发头 —— 于是任何成员都能把 \`sender_id\` 填成别人的，接收端按
\`sender_id\` 区分说话人，这就是**冒充**。

**修订**：AEAD 之后加一步 \`header.sender_id == session.sender_id\`，不符则丢弃并单独计数
（\`sender_mismatch\`）。放在 AEAD 之后是因为只有包确实由这条会话的密钥签出时，
「不一致」才意味着冒充而不是线路噪声。

### 12.5 \`sender_id = 0\` 保留给服务器，且服务器自己发的包要有独立序号

BindAck / ProbeAck 是服务器生成的，没有「说话人」。若它们的 \`sender_id\` 都填 0、
\`seq\` 也复用（例如都填 0），那么**重绑定两次就会用同一个 \`(key, nonce)\` 加密两条不同的
BindAck** —— ChaCha20-Poly1305 下 nonce 复用是灾难性的。

**修订**：\`sender_id = 0\` 保留给服务器（真实发送者从 1 开始分配）；服务器为每条会话维护
独立的 \`server_seq\`，每条服务器生成的包取一个新值。这条有测试钉住。

### 12.6 fan-out 的原地加密必须每轮重新拷贝明文

实现细节，但值得写下来：服务器用一块复用缓冲做 fan-out，而 AEAD 是**原地**加密的。
如果只在循环外拷一次明文，第二个收包人拿到的就是「上一轮的密文再加密一次」。
每一轮都必须从明文重新拷一份。

### 12.7 与 §11 一致性检查的关系
